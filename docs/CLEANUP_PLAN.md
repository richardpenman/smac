# Cleanup plan

Goal: turn the faithful reconstruction into code that is pleasant to modify: meaningful names,
game-state objects, small functions, unit tests. **Behaviour stays identical** to the original
`terranx.exe` at every commit. Original bugs stay on by default, but each one sits behind a
named switch.

Starting point (cfe8a1b):

| | |
| --- | --- |
| Code | engine ~47k lines, UI ~48k lines, 1402 `ADDR`/`ADDR_NATIVE` functions, 581 `GLOBAL` + 53 `GLOBAL_NATIVE` |
| Hard spots | `base_build` ~2.2k lines, `order_veh` 1.3k lines with 176 gotos, `enemy_move` (state machine over the original's stack frame), 506 gotos (335 engine, 171 UI), 173 `BUG(original)` |
| Proof | 29 harness scenarios natively; hybrid and fcompare against the original under Wine; ASan; 10 scripted UI suites; observer games of smacx |

## 1. The invariant and the gate

Every commit passes `src/tools/gate.sh`. The script exits non-zero on any failure and writes
`work/gate/summary.txt`.

| Step | What it proves | Command it runs |
| --- | --- | --- |
| `static` | No original address was lost or added. The names table is current. Every fcompare entry names a declared function. Every `BUG(original)` site names a declared compat flag, and docs/COMPAT.md is current. | `src/tools/names.py check`, `src/tools/compat.py check` |
| `build` | Native, ASan and hybrid builds compile | `cmake` into `$GATE_PREFIX-{native,asan,hybrid}` |
| `unit` | Unit tests pass, also under ASan; the original's recorded results of 197 functions still hold | `ctest` (smoke, `smacx_unit`, the golden replays, `names.py check`), ASan `smacx_unit` and golden replays |
| `native` | The game is identical to the original on all 29 scenarios | `harness/verify.sh native <all>` |
| `observer` | smacx, with every UI area replaced, plays observer games identical to the original's | `smacx --human 0 --snapshots` vs `work/ref`: tiny20 small12 std8 late140 |
| `asan` | No memory or UB errors, same game | ASan `smacx_headless` + `compare.py`: tiny20 small12 std8 late140 council131 |
| `hybrid` | Each reconstructed function still drops into the original | `harness/verify.sh hybrid all` tiny20 small12 std8 late140 |
| `diffnative` | After the hybrid freeze: the native build plays new seeds and the 29 scenarios exactly as the frozen `hybrid-final` build does. Runs only when the baseline exists. | `src/tools/diffnative.sh --baseline $GATE_BASELINE` (default `hybrid-final`) |
| `fcompare` | Function by function against the original. Run when a commit touches the functions listed in `GATE_FCOMPARE`. | `harness/verify.sh fcompare "$GATE_FCOMPARE"` |
| `ui` | The scripted UI behaviour is unchanged, with no memory or UB errors | `tests/*/run.sh` (animated: `smacx --animate`, every slide, move, boom and movie played) with the native smacx, then with the ASan smacx (no sanitizer report in any case's log) |

When to run what:

* Per commit: `src/tools/gate.sh` (about 17 min on 2 cores with incremental builds; measured on the first increment).
* While working: `src/tools/gate.sh --quick` (one scenario each for asan and hybrid), or
  `--only static,build,unit,native`.
* Any commit that changes a function body: also
  `GATE_FCOMPARE="none +fn1 +fn2" src/tools/gate.sh --only build,fcompare`.
* Commits that only rename or reformat: the build and the gate above are enough. A reformat can
  also be checked by comparing objects built with `-g0`. Their `.text` sections must be
  byte-identical.

The gate never creates oracle references (`work/ref`). A missing reference fails the step.

## 2. Names and the hybrid build

The hybrid build patches by address. `gen_bindings.py` reads `ADDR(0x...)` and uses the name only
as a C++ symbol. fcompare and patch specs also use the source name (`"none +vector_dist"`).

| Option | Pro | Con |
| --- | --- | --- |
| A. Keep `ADDR` on every renamed function. Record the original name in a table. | Hybrid, fcompare and the patch table keep working unchanged. Per-function proof against the original stays available for as long as signatures stay ABI-compatible. | Signatures must stay cdecl with 32-bit arguments. The state must stay in the image. |
| B. Freeze the hybrid/oracle now and verify only natively | Free to change signatures and state at once | Loses per-function proof exactly when functions get split and renamed, the riskiest phase |

**Recommendation: A until the state leaves the memory image (phase 5), then freeze.** Details:

* `re/original_names.tsv` (generated by `src/tools/names.py update`) maps
  `addr → original name (FUN_… or symbol) → source name → header`. `names.py check` is part of
  the gate, so a rename can never silently drop an `ADDR`. `names.py lookup FUN_004e7e50` or
  `lookup base_tile_intake_add` finds either side.
* `src/tools/rename.py OLD NEW` renames across src, harness (fcompare table, patch specs), tests and
  docs, then refreshes the table. It refuses names that already exist.
* A split function keeps its `ADDR` on the entry point. Extracted helpers get no `ADDR`. Hybrid
  patches only entry points, so splitting stays verifiable by hybrid and fcompare.
* **Freeze point:** the first commit whose state no longer lives at the original addresses, or
  whose signatures can no longer be cdecl. Tag it `hybrid-final`. After that, verify
  native-vs-native: the `hybrid-final` build becomes the reference, alongside `work/ref`.
  Snapshots of both builds are compared on the 29 scenarios **and on any number of new seeds and
  saves** (cheap, no Wine). This is stronger coverage than the 29 references alone.
  `src/tools/diffnative.sh` does it (increment 18); the gate's `diffnative` step runs it once the
  tag exists.

## 3. Globals become game-state objects

The constraints: savegames stay byte-compatible, and the `.state` snapshots stay comparable with
`work/ref` (they are dumps of image regions).

| Option | Pro | Con |
| --- | --- | --- |
| A. Keep the image as the backing store, with typed accessors and objects as views over it | Zero risk. Hybrid keeps working. Save and snapshot need no change. | 32-bit layouts stay. Pointers can't live in the state. Fixed array sizes. |
| B. Native containers with explicit save/load serialisation. The image is kept only for the hybrid. | Free modern design (vectors, real pointers, no size limits) | Large step. Needs serialisation code for every record, plus a snapshot writer. |

**Recommendation: staged, A first, B behind the hybrid freeze.**

1. **Group** (A): `struct GameState` holds reference members onto the image: `factions`,
   `bases`, `vehs`, `map` (dimensions + tiles), `rules`, `turn`. One `game()` accessor. Code moves
   from `Bases[i]` to `game().bases[i]` mechanically, one module per commit. Layout is unchanged.
2. **Methods** (A): logic moves into non-virtual member functions of the layout structs (`BASE`,
   `Faction`, `VEH`, `MAP`). Struct layout and `SMAC_LAYOUT` asserts are untouched. Free
   functions with `ADDR` stay as one-line forwarders for as long as the hybrid lives. Example:
   `base_growth()` on `CurrentBaseID` → `Base::growth()`.
3. **Scratch globals** (the ~250 `Base*`, `Diplo*`, `Veh*` work variables that pass data between
   functions) become locals or context structs passed explicitly. Do this function group by
   function group. Where the original reads stale values across calls (docs/RECONSTRUCTION.md,
   "Known uninitialised reads"), the emulation becomes a named field of the context, never
   implicit.
4. **Freeze the hybrid**, then (B): the state moves into native objects. `save.cpp` reads and
   writes records in the original byte layout through explicit `serialize(Writer&)` functions.
   The snapshot writer emits the same `.state` regions from the objects, so `work/ref` stays the
   golden reference. The image then only seeds the initial data (rules defaults, tables), until
   those are re-created in source.

## 4. `BUG(original)` behind named compatibility code

* `engine/compat.h`: `struct Compat { bool read_after_kill = false; ... }` plus `inline Compat
  g_compat;`. A flag `true` plays the original's bug, `false` its fix.
* User decision (after increment 9): smacx plays with every fix by default; one switch,
  `--original-bugs` or `Original Bugs=1` in the ini (`compat_set_original_bugs`), turns every flag
  on, i.e. the game exactly as terranx.exe plays it. There is no per-bug user option; the single
  flags stay for the code and the tests. Everything compared with the original runs with the
  original bugs: `harness/verify.sh` (`smacx_headless --original-bugs`), the gate's observer and
  ASan steps, the hybrid DLL (forced on in `DllMain`: patched functions must behave as the
  original's), the scripted suites (see docs/DEVELOPMENT.md). Multiplayer: a hotseat/PBEM save
  carries the setting (a mark in the legacy preferences block, engine/save.h), an online host
  sends it (0x0F10).
* Each site is `if (g_compat.flag) { original } else { fixed }`, a named helper (e.g.
  `engine/compat_reads.h` for the out-of-range reads, `ai_base_slots()`), or for a few flags
  whose fix equals the reconstruction's emulation (stack residues read as 0) a comment naming the
  flag. A flag whose fix is deliberately not written keeps `COMPAT_ORIGINAL(flag)` and its
  comment says why ("Not fixed:"); five do (see docs/COMPAT.md).
* The fixed paths have unit tests where they are reachable without game data
  (tests/unit/test_compat_fixes.cpp, including the guarded readers); the gate's `fixes` step
  plays scenarios with the fixes under ASan.
* The stack-residue emulations (`g_stack_residue`, `EM` slots) are compat items too, grouped in
  `Compat::StackResidue`.
* The catalogue is generated from the flags (`docs/COMPAT.md`: what each bug does in play, the
  fix, the files).

## 5. Naming conventions

| Kind | Convention | Notes |
| --- | --- | --- |
| Free functions | `snake_case`, verb first | Keep meaningful original/Thinker names (`base_production`); rename `FUN_*`, `*_unused_helper_*` and `_2`/`_3` overload suffixes (`vector_dist_2` → `tile_distance`) |
| Types | `PascalCase` | Layout structs keep their names until phase 5 (`BASE` → `Base` via alias first) |
| Members / locals | `snake_case` | No `iVar3` / `local_28`. A stack-slot name survives only as a comment where docs refer to it. |
| Globals (while they exist) | `PascalCase` (as now) | `dword_XXXXXX` / `DAT_` names (36 left) are renamed first |
| Constants | `kPascalCase`; enums `enum class` | Magic numbers → named constants (`0x8000008` → `DIPLO_PACT_COMM`) |
| Files | module names as now; new classes get their own file | |

Rename process: `rename.py` for unique free functions and globals (word-level, then build and
gate). Use clangd's rename (`compile_commands.json` is in every build dir) for members, locals
and overloaded names. One rename batch per commit, with no other change in the same commit.

## 6. Splitting giant functions, removing gotos

Rules, all from the fidelity contract:

* Random draws keep the same order and count.
* Side effects keep their order.
* Short-circuit conditions keep their evaluation order.
* Early-exit loops still exit at the same element.
* Stack-residue emulations stay explicit.

Approach:

* Extract pure computations first (scores, conditions) into named functions. Then extract
  role-specific blocks into functions that take a context struct. A `goto` to a shared join point
  becomes a `return` of an enum, which the caller dispatches. `enemy_move` already does this with
  `Flow`.
* Before splitting, run coverage (`SMACX_COVERAGE`, `coverage_report.py --missed`). Every block
  being moved must be executed by a scenario or fcompare. Otherwise add a scenario first.
* fcompare the entry point after each split (`GATE_FCOMPARE`).

Order (by how often a modder needs to touch it, then by risk):

| # | Function(s) | Size | Notes |
| --- | --- | --- | --- |
| 1 | `base_production`, `base_growth`, base yields (base.cpp) | ~540 lines | most-modded rules |
| 2 | `battle_resolve`, combat odds (battle.cpp) | | combat rules; unit-test odds |
| 3 | `base_build` (base_misc.cpp) | ~2.2k lines | AI production choice |
| 4 | `goody_box`, `probe`, `random_events` | 550–650 lines | 22/25 gotos |
| 5 | `order_veh` (move_order.cpp) | 1.3k lines, 176 gotos | movement rules; stack residue #5 |
| 6 | `enemy_move`, `air_power`, `enemy_strategy` (ai*.cpp) | largest | last: stack residues #2, #3 |

## 7. UI: structs at offsets become classes

The UI is not part of the hybrid build. It is verified by `tests/*/run.sh`, the observer check
and the screenshot comparisons (`tests/*/compare.sh`, which need Wine).

1. Window objects that live in the image (MapWin `kMw*` offsets, Console, BaseWin) get a typed
   view: a struct of the original layout with `static_assert(offsetof)`, replacing the
   `mapwin_field(win, kMwZoom)` reads. No behaviour change.
2. Natively owned windows (`MapWinNative`, `SocialWinState`, popups) become classes with
   constructors and member functions. Vtable emulation is replaced by virtual functions once no
   engine code reaches the window through the bridge.
3. The remaining `FUN_*` method comments in src/ui (86 addresses) get names when their class is
   cleaned.

## 8. Unit tests

* Framework: **doctest 2.4.11**, vendored (`third_party/doctest`, MIT). Target `smacx_unit`, run by
  `ctest` and the gate. No game data needed. Tests set image globals through `SaveGlobal` /
  `MapDims` (`tests/unit/unit.h`).
* First tests (done): util (`quick_root`, `stoi`, `fixed_div`, …), map geometry (`vector_dist`,
  `x_dist`, `compass_index`, `radius_move`, …), text substitution (`parse_string`), random
  generators. All of them are fcompare-verified or on every harness path. Expected values are
  derived from the original's code and document its quirks. One test already pins a duplicate:
  `veh_vector_dist` equals `tile_distance`.
* Next: rules lookups (`proto_cost`, `arm_val`, `weap_val`), combat odds (`battle_compute`
  pieces after the split), terrain math (`crop_yield`, `mine_yield` on a synthetic map), base
  growth formulas, social effects (`social_calc`), save round-trip (load a save, write it, compare
  bytes).
* **Golden tests from the original** (done, increment 17): an fcompare mode records `(arguments,
  state hash) → result` of the original for pure functions into `tests/golden/<fn>.tsv`, once,
  under Wine. A data-dependent test category (ctest `golden_*`, skipped without `game/` and
  `data_image.bin`) plays the scenario natively and replays the records at their turns. This keeps
  original-checked function tests alive after the hybrid freeze.
* Every split or rewritten function gets unit tests for the extracted pure parts in the same
  commit.

* `/.clang-format` is the style. The whole tree (src, tests, harness; not third_party/, which has
