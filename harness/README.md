# Differential harness

Runs the original `terranx.exe` (under Wine + Xvfb, with an injected DLL) and the reconstruction
on the same scripted scenario, and compares the game state turn by turn.

| Piece | Role |
| --- | --- |
| `oracle/oracle.cpp` → `oracle.dll` | Makes the original scriptable and deterministic. |
| `oracle/oracle.cpp` → `hybrid.dll` | Same, plus the reconstructed engine jump-patched over original functions. |
| `oracle/launch.c` → `oracle_launch.exe` | Starts terranx.exe suspended and injects the DLL. |
| `../src/app/headless.cpp` → `smacx_headless` | Runs the same scripts on the pure reconstruction. |
| `run_oracle.sh` | One isolated oracle/hybrid run (own run dir, pristine ini, own X display). |
| `verify.sh` | Run scenarios in hybrid or native mode and compare with cached oracle references. |
| `compare.py` | Field-level diff of two snapshot directories. |
| `state_regions.h` | The game-state memory regions that are compared. |
| `scenarios/*.cmd` | Standard scenarios. |

## Determinism measures (oracle side)

The unmodified game is not reproducible: it seeds from the clock, UI effects consume the gameplay
random stream, and some engine code uses `timeGetTime()` as randomness. The oracle therefore:

* reseeds both generators from the script (`seed`);
* redirects game-LCG calls made from UI code (palette cycling etc.) to a private generator
  (`ui_rng_sites.h`, generated by `oracle/gen_ui_rng_sites.py`);
* hooks `timeGetTime()`: eight engine sites that use it as randomness read a deterministic logic
  clock (+7919 per read, mirrored by `engine_logic_time()`); other engine reads only pace
  animations and get a fast-forward clock; UI code gets real time;
* plays all factions as AI with faction 0 as the viewer, skips the observer "turn complete" pause,
  and disables tutorial, autosave, movies and battle pauses;
* forces popups through `BasePop_exec_3`'s no-display path (announcements are shown to everyone);
* disables the cosmetic UI timers;
* answers Planetary Council sessions for the observer (see "Planetary Council sessions" below);
* skips the end-of-game screens and stops with a final `game_end` snapshot (see "End of game");
* **poisons the stack** (fills 32 KB below the caller with a fixed byte) before `turn_upkeep`,
  `faction_upkeep`, `enemy_turn` and every `enemy_veh` call. The original AI reads an
  uninitialised local somewhere below `enemy_veh`: without poisoning, roughly one run in four
  diverges (a sentried unit is or is not woken) depending on stack contents left behind by
  timing-dependent UI code. With poisoning, every run matches, and fill values 0x00 and 0xFF give
  identical games, so this poisoned behaviour is the canonical one the reconstruction reproduces.
  (The exact read has not been located yet.)
* **poisons `wants_to_attack`'s slot array** (known uninitialised read #4 in
  docs/RECONSTRUCTION.md): every call site that starts an evaluation (a single call, or the
  first `(a, b)` call of an `(a, b)` / `(b, a)` pair: wants_prop, diplomacy_check, propose_attack,
  threaten, call_off_vendetta, communicate, encounter, enemy_strategy, tech_val; list
  `kWantsToAttackFirstSites`) calls a thunk that fills exactly the 8 dwords
  `[entry ESP - 0x138, entry ESP - 0x118)` (the array at `[ebp-0x134]`) with the poison value and
  enters 0x55BC80 at the original stack depth. The second call of a pair is not touched, so it
  still sees the first call's reduced slots, as in the original; no other dead stack changes.
  Without this the slots hold whatever earlier frames left at that depth, e.g. in
  `spot_all -> encounter` the frames of `draw_radius` / `MapWin_draw_radius` / `GraphicWin_redraw`
  and the Win32/DirectDraw code below them (late140, turn 142: 0x014101C1, 0x7A6D9ADF, ...),
  which a headless build cannot reproduce. Slot values 0 and -1 behave alike, so fill values 0x00
  and 0xFF give identical games. Native equivalent: `WantsToAttackResidue` is 0 at the start of
  every evaluation and keeps the first call's values for the second call of a pair. (`steptrace`
  treats the thunk as an external call, so a call entered through it is not traced.)

## Reconstructed game loops

`control_game` and `control_turn` are reconstructed; the harness reaches them through hooks
(`g_harness_*` in `src/engine/turn.h`). The reconstructed `enemy_turn`/`enemy_veh` call `g_harness_enemy_veh` and
`g_harness_enemy_veh_pump` (`src/engine/ai.h`) at the call sites the oracle patches in the original
(enemy_turn -> enemy_veh, and enemy_veh's message pump), so stack poisoning happens there too. `smacx_headless` runs `control_game`, which calls the
command script in place of the main menu; hybrid.dll sets the same hooks to the oracle's call-site
hooks (snapshots, fcompare, stack poisoning, observer pause, script), so the patched loops behave
like the original ones under the oracle.

## Script commands

```
outdir <dir>          snapshot directory (run_oracle.sh / --outdir override it)
seed <crt> <game>     reseed MSVC rand() and the game LCG; resets the logic clock
newgame k=v ...       new game without dialogs; keys: size(0-4) width height ocean erosion orbit
                      clouds natives diff rules(hex) factions=a,b,c,d,e,f,g
                      random(bit 0: random leader personalities, bit 1: random social agendas)
load <file.sav>       load a saved game
save <file.sav>       save (RNG state preserved)
snapshot <name>       write <name>.state/.rng/.sav now (headless: no .sav before newgame/load)
dumprules <file>      write all rule tables as text into the output directory (harness/rules_dump.h)
turns <n>             run the real turn loop; snapshot turn_NNN before each turn_upkeep; exit after n
viewer <faction>      faction whose view is shown (default 0)
trace <n> [turn]      1: log RNG at each faction step; 2: also dump state per step;
                      3 <turn>: dump state before every enemy_veh on that turn;
                      4: log vehicle order changes and a state hash at every step
watch <turn> <hex>    hardware write watchpoint on a byte, armed at that turn's turn_upkeep
logcalls <turn>       log calls of spotting/waking functions from that turn on
poison <byte>         stack fill value (default 0)
poison rand <seed>    pseudo-random stack fill (detects uninitialised reads that 0/0xFF hide)
poisonpump            also poison after enemy_veh's message pump (do_all_non_input, 0x57928D);
                      makes the oracle reproducible where a dispatched message leaves frames in
                      enemy_move's area (enemy_move reads [ebp-0x48] uninitialised at 0x574DD7)
steptrace <turn> <veh|-1> [max]  single-step enemy_veh calls, write step_*.trc register traces;
                      analyse with tools/venv/bin/python harness/scripts/uninit_reads.py X.trc
                      [--summary --engine] (reads of released/unwritten stack, with writer)
slotlog <func> <prologue_len> <off>...  log return address, 8 args, [entryESP+off] dwords and
                      EBX/ESI/EDI/EBP at each entry of an original function (logger runs on a
                      private stack; the caller's register locals and frame are visible this way)
patch <spec>          hybrid only: all | none | +name | -name ...
fcompare <from> <to> [hooks=turn,faction,enemy] [limit=<pure>,<mut>] <spec>
                      hybrid only: compare original and reconstructed functions on the live
                      state at the selected hooks of turns from..to (see "Function comparison")
hangdump <seconds>    log where the main thread waits after that many seconds without progress
quit
```

`PATCH_SPEC="..."` (run_oracle.sh / verify.sh) applies a patch spec at DLL load, before the game
boots, so reconstructed boot code runs too.

## Snapshot files

* `NAME.state` — records `{u32 addr, u32 size, bytes}` for every region in `state_regions.h`.
* `NAME.rng` — `crt`, `game`, `clock`, `turn`.
* `NAME.sav` — the game's own save (contains heap pointers and UI state; compared only with `--sav`).

## Planetary Council sessions

`council` (0x428350, called by `call_council` from `faction_upkeep`, or by `control_turn`)
opens the council window (`CouncilWin`, vtable 0x66AAE8) through FUN_00427230. That function
computes every non-human faction's vote with `council_get_vote` (three passes) and then enters the
window's modal loop (`Win_set_modal`, vtable+0xE4, called at 0x4282F2). In single-player the loop
has no timeout (the 60 s per human limit is a multiplayer feature): the session is only decided
when the viewer votes, and only closed when the viewer then presses Enter / the close button.
An unattended observer therefore waits forever: the probe131 game (long300 turn 120 reseeded
1120/2120) at the end of turn 131 (governor election), and long300 itself at the end of turn 147
(Global Trade Pact, then a governor election). `hangdump` shows the main thread in
0x5EE24C (Win_set_modal) <- 0x4282F8 (FUN_00427230) <- 0x4284CF (council) <- 0x52D9C7
(call_council) <- faction_upkeep. Scenarios past these points: council131, late147, long300 (now
runs all 300 turns) and end300 (to the end of the game).

What the viewer's input does in the original:

1. A vote button (YEA/NAY/ABSTAIN, or VOTE + the GOVVOTE candidate popup in elections) calls
   FUN_00424720(viewer, vote): it stores the viewer's vote, recomputes the votes of all living
   non-human factions with `council_get_vote` (three passes, as when the window opened), redraws,
   and tallies (FUN_00424410(1)). The tally counts **factions 1-7 only** (YEA -1 and NAY -2
   weighted by council votes; abstentions -3 and dead factions -5 not counted; Supreme Leader
   needs 3/4); it sets the session result (1 passed, -1 failed or no governor majority, -2 vetoed
   by the governor's NAY), clears the per-faction vote-buying fields
   for the proposal, sets `ProposalCallTurn[proposal]`, and for an election sets `GovernorFaction`.
2. Enter (FUN_00425BA0 with key 0x0D, also what the close button sends): for a non-human viewer it
   releases the modal state, closes the fonts and windows and, when the proposal passed, calls
   `council_action(proposal, winner)`.

The oracle (`install_council_hook`) replaces the modal loop call by exactly these two calls
(FUN_00424720 then FUN_00425BA0), with the vote the window already holds for the viewer's faction.
For the default viewer, faction 0, that vote is not counted at all, so the outcome is decided by
the seven AI factions' own votes, independently of which button an observer would press; this is
the result every attended observer game gets as soon as the observer clicks any vote button and
closes the window. (For `viewer <f>` with an AI faction f, f keeps its own AI vote, as if the
observer had confirmed it; pressing ABSTAIN instead would change f's vote.) Not reproduced: the
alternative of closing the window without voting, which skips the tally and `council_action`
(only `ProposalCallTurn`, set by `council` itself, would change). Hotseat, PBEM, multiplayer and
human viewers keep the original modal loop. Each session is logged in `oracle.log`
(`council turn=... proposal=... votes=...` and `council result=...`). A native reconstruction of
`council` must reproduce this: AI votes, the extra three `council_get_vote` passes, the tally and
`council_action` when passed. The reconstruction (engine/council.cpp) runs the modal loop through
`ui_councilwin_modal`: hybrid builds call the oracle's hook there (`g_harness_council_modal`),
`smacx_headless` does the same two steps itself.

## End of game

When a game ends (time limit, council or economic victory, ...), `end_of_game` (0x524870) first
does the game-state part (victory type 0x9B206C, monuments) and then shows the end screens:
`show_credits`, `report_score(1)`, `quayle` (rating), `hall_of_fame(1)` (reads and writes
`hallfame.jhh`), `show_replay` (saves "Alpha Centauri Autosave 1", replays the map history and
reloads that save), and the GAMEOVERMAN popup; `control_game` then reloads the game and returns to
the main menu. All of these are UI with modal loops; `report_score` even crashes with viewer 0
(ReportIf_on_status, 0x4A5C7E, calls a per-faction button indexed by faction 0). The oracle
replaces the first four with no-ops and, when `show_replay` is called, writes the snapshot
`game_end` (state after the victory processing, `GameState` with STATE_GAME_DONE) and exits with
code 0. The `turns` limit is then not reached; the run ends at the game's end. `smacx_headless`
does the same: its `show_replay` calls `g_harness_game_end` (engine/turn.h), which writes
`game_end` and exits; the other end screens are no-ops headless. `compare.py` compares `game_end`
after the turn snapshots.

## Hang diagnosis

`hangdump <seconds>` (default 60; 0 disables): when the game loop makes no progress for that long,
a watchdog thread logs a `HANG` line to `oracle.log` with EIP, the modal window stack
(`WinModalState`, top window and its vtable) and the return addresses into terranx.exe found on
the main thread's stack (repeated every period). It is armed by `turns` and only reads state.
`run_oracle.sh` also takes a screenshot (`hang.png`) shortly before its timeout. A crash (`CRASH`
line) is logged with the same return-address scan.

## Function comparison (`fcompare`)

`fcompare` (hybrid.dll, `harness/oracle/fcompare.cpp`) checks reconstructed functions one by one
on real game states, independently of whether a whole game stays in sync. At each selected hook
(default: before every `turn_upkeep`; `hooks=turn,faction,enemy` adds the starts of
`faction_upkeep` and `enemy_turn`) every selected function is called with generated arguments:

1. the original (its jump patch, if active, is removed for the call), then
2. the reconstruction,

each on the same state: the memory image (0x682000-0x9CA000), the map tiles and both random
generators are saved before and restored after each call, and the stack below is poisoned. For
every call the return value, out-parameters and string buffers are compared, and the random
generator states; for functions marked as mutating also the resulting memory image (except the UI
ranges listed in `kFcIgnore`) and map. Pure functions are checked once per hook for unexpected
memory writes. The game itself continues unaffected (snapshots stay identical to the reference).

Arguments come from `harness/oracle/fcompare_table.h`: one entry per function with its flags
(`FC_MUTATES`, `FC_VOID`) and up to eight argument domains (`FA_FACTION`, `FA_VEH`, `FA_BASE_OPT`,
`FA_UNIT`, `FA_TECH`, map tiles `FA_X, FA_Y`, `FA_RANGE`, `FA_BIT`, out-parameters `FA_OUT`,
string buffers `FA_STR`, int32 array buffers `FA_BUF`/`FA_BUF_OPT` (16 seeded values in lo..hi, compared), ...). Small domains are enumerated completely; larger ones are sampled
deterministically, at most `limit` calls per function and hook (default 2000 pure / 100
mutating). **Add an entry for every function you reconstruct** (cdecl, integer/pointer arguments;
THISCALL methods are not supported). Choose domains that avoid viewer dialogs (e.g.
`FA_FACTION1` instead of `FA_FACTION` where faction 0 would pop up a message).

The spec selects table entries like patch specs: `all`, `none`, `+name`, `-name`. Results:
`fcompare.log` (per hook totals and the first 20 mismatches per function, with arguments and the
first differing memory byte, e.g. `Vehs[12]+0x11`) and `fcompare_summary.txt` (calls and
mismatches per function, cumulative) in the output directory; per-hook totals also in
`oracle.log`. Convenience wrapper:

```sh
HYBRID_BUILD=build/$ME-hybrid harness/verify.sh fcompare "none +veh_init +spot_all" tiny20 late100
FCOMPARE_OPTS="hooks=turn,enemy limit=5000,200" harness/verify.sh fcompare all small12
```

It runs each scenario with no patches, prints the functions with mismatches, those never called
(empty domains, e.g. no bases yet) and `PASS`/`FAIL`. A mismatch means the reconstruction behaves
differently from the original on that state with those arguments: fix it (the log line gives a
reproducible case). Caveat: callees run as originals in the first call and as reconstructions in
the second, so a mismatch can also come from a reconstructed callee; compare callees first.
